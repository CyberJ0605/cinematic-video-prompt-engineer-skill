# Cinematic Video Prompt Engineer

> 电影感视频提示词工程师：把剧情、小说片段、人物关系或一句场景想法，转译成能拍、能演、能生成的电影感 AI 视频提示词。

![workflow](https://img.shields.io/badge/workflow-direct%20%7C%20reference--first-6f42c1)

![platform](https://img.shields.io/badge/platform-Agent%20Skill-black)

这个 Skill 不靠堆砌“电影感、高级感、氛围感”等形容词。它会先诊断剧情中真正可见的事件、冲突与情绪转折，再分配时长、结构、镜头、表演、台词、声音、光影和连续性，最终生成可直接交给 Seedance、Kling、MiniMax H3、Wan3.0、海螺等主流视频模型的提示词。

它既可以直接生成自包含的视频提示词，也可以先规划并生成角色、场景、关系和关键道具参考图，再根据实际选中的图片编译视频提示词。

## 快速开始

1. 安装 `cinematic-video-prompt-engineer` skill。
2. 在支持 Skill 的 Agent 工具中输入：`请用 $cinematic-video-prompt-engineer 处理这个剧情：……`
3. Skill 会判断合适的时长与结构；收到小说或剧本且尚未选择制作路径时，先询问直接视频还是参考图优先，已确认或委托选择时不重复询问。
4. 直接视频路径会输出完整视频提示词；参考图优先路径会先输出素材规划与文生图提示词。
5. 如果你提供生成结果并说明问题，Skill 会锁定成功部分，只修改失败变量。

## 当前版本重点

- **角色卡与场景资产**：主要人物默认直接编写角色卡提示词；先确认基础资产，再按需制作关系图或首帧。场景资产落实摄影布光，需要反向或复杂空间视角时，先明确关键物件、布局与机位可见性。
- **交付检查与资产覆盖**：参考图模式按选定改编范围完整盘点主要人物、场景、关键道具及必要状态，逐项落实已有、新增或共享覆盖；视频提示词交付前检查实际草稿，修正问题后再呈现。
- **指定时长适配**：优先删减助手自行增加的设计；用户核心内容仍放不下时，说明瓶颈并建议延长、压缩或拆分，不把内容硬塞进指定时长。
- **轻量多模态参考**：区分图片、视频和音频的采用范围，按场景启用；动作参考不自动继承人物场景，音色参考不自动继承台词或配乐。
- **反转叙事**：区分客观事实、角色感知与观众理解，用前后兼容的画面和声音线索完成回溯式反转。
- **跨片段导演控制**：尾帧只承接可见状态，不默认复制构图；逐镜检查参考图覆盖、切点、空间关系和机位动机。
- **多人打戏**：按交接威胁、动作可读性和武器/道具状态组织1对多攻防，不机械堆砌招式。
- **一镜到底情绪覆盖**：让脸部、视线、手部接触、走近过程和结尾反应都在连续镜头中获得可读的画面证据。
- **双生产路径**：区分“直接视频路径”和“参考图优先路径”，不再把两套控制逻辑混进一条提示词。
- **参考图编译**：实际图片像素高于此前文字设想；视频提示词只补动态变化，不重复整段静态外观。
- **可控表演**：用心理动机、保护层、眼神、呼吸、停顿、声线、身体联动和物理接触组织“活人感”。
- **密集对白**：支持抢话、短暂重叠、口误、未完成句、画外音、说话者/听者双轨与语义剪辑点。
- **横竖屏路由**：默认低风险场景采用16:9；选择9:16时会重新组织景别、站位和运镜，而不是简单裁切横屏构图。
- **专项参考库**：新增46种运镜模块和25种可观察情绪表演模块，按剧情功能选择，不整库照抄。
- **结果局部修复**：视频或参考图生成失败时，保留成功部分，只改失败字段及必要联动项。
- **6-30秒自适应**：按真实可播放内容决定时长，并为不同片长设置提示词目标区间与上限。

## 工作方式

### 1. 先选择输出模式

| 模式 | 适用情况 | 主要输出 |
|---|---|---|
| 精简模式 | 用户明确要求“只给最终提示词” | 最终视频提示词 |
| 打磨模式 | 普通创作与修改，默认模式 | 剧情诊断、电影化策略、当前生产阶段的交付物 |
| 方向确认模式 | 用户明确要求先讨论，或核心事实确实无法推断 | 诊断、策略、一个待确认决策 |
| 连续短片模式 | 长剧情拆分、系列短片或续写 | 连续性摘要、角色/场景锚点、分段提示词与衔接方式 |

方向确认不是固定流程。已经确认的方向不会重复询问，用户说“按你的建议”或明确授权创作时，Skill 会继续完成交付。

### 2. 再选择生产路径

#### 直接视频路径

适合单人物、单场景、视觉漂移风险较低，或用户明确要求直接生成视频提示词的任务。最终提示词会自带必要的人物、场景、服装、道具、光影、声音和开场状态。

#### 参考图优先路径

适合古装造型、多主要人物、重复场景、复杂空间、关键道具、产品结构、连续短片或对人物一致性要求高的任务。

```text
阶段1：剧情诊断与电影化策略
阶段2：参考图素材规划与文生图提示词
阶段3：生成、选择或上传实际参考图
阶段4：检查图片并编译参考图驱动的视频提示词
阶段5：根据生成结果做局部修复或继续下一段
```

在参考图驱动版本中，实际选中图片里的可见事实优先。视频提示词主要描述动作顺序、表演变化、镜头发展、台词、声音、转场和最终状态，不重复塞入整段静态人物设定。

### 3. 小说、剧本与长文本：先统筹，再逐场交付

支持将已有小说、剧本和连续剧情改编为分段视频提示词，不等于代写完整小说或一次输出整部长片。先区分改编范围：

- **精选片段／高光**：整理可拍摄片段，按要求选择并改编，不承诺覆盖全文。
- **完整改编／完整覆盖**：先整理所选原文范围的全文事件结构、人物关系和必要的人物／场景／关键道具资产清单，再按场次分批编写视频提示词；不能因原文较长而擅自改成高光摘选。
- 每批标明已完成与剩余的原文／片段范围、当前人物与道具状态及下一步。一个场次可拆为多条不超过30秒的视频提示词；拆分依据是动作、对白、表演和衔接能否自然完成，不是按原文字数机械切段。

资产清单是规划，不代表已经生成图片。直接视频路径不强制制作资产图；参考图优先路径仍按实际资产及确认状态推进。用户明确要求先看结构时停在该阶段，否则不因完成结构表而额外增加审批。

**能力边界：**Skill不规定小说／剧本输入的硬性字数上限；参考库中的约1500／3000字分档仅用于估算工作量。实际单次接收与交付容量受使用的Agent、上下文和输出限制影响，不保证数万字一次完整处理或一次交付全部成品。可以先提供整体材料统筹，再逐章／逐场细化；缺失、无法读取或尚未处理的内容应明确标出，不能声称已完整阅读或覆盖。

连续性记录不等于自动持久化或跨对话自动恢复。当前不应视为已经验证的整部长篇自动项目管理系统；长期项目应保留原文索引、结构表、人物／资产清单和批次交接记录，新对话继续时重新提供。文本自检也不能保证生成视频的最终质量。

## 核心原则

1. **先判断能否被拍出来**：把抽象情绪改写为可见、可听、可计时的表演和事件证据。
2. **时长服从内容**：不为凑满 30 秒拖慢节奏，也不把超量剧情硬塞进单条视频。
3. **表演由动机驱动**：眼神、表情、呼吸、停顿、语气和伴随动作必须服务于同一心理目的。
4. **镜头必须有任务**：景别、机位、运镜和剪辑都用于揭示信息、推进关系或放大情绪，而不是堆砌术语。
5. **连续性优先于装饰**：锁定人物、场景、道具、轴线、光源、声线和空间关系，再设计变化。
6. **只声明真正完成的检查**：提示词文本通过自检不等于生成效果已经验证，最终效果仍以实际视频反馈为准。

## 适合用于

- 6-30秒横屏或竖屏AI视频
- 一句话剧情、人物关系、场景想法和小说片段改编
- 情绪特写、亲密张力、告别、争吵、重逢与克制表演
- 原生同步对白、多人抢话、都市家庭戏和长台词情绪递进
- 悬疑、短剧钩子、信息差、发现与反转
- 古装、产品、人物质感、群像、大场面和近身动作戏
- 需要先建立人物、场景、关系或关键道具参考图的项目
- 长剧情拆分、连续短片、尾帧续写和跨片段一致性维护
- 已生成视频或参考图的定向修复

## 不适合直接用于

- 完整长片、长剧本或小说正文写作
- 标题、口播稿、营销文案和纯图片设计
- 把大量剧情机械压进一条30秒视频
- 依赖大量字幕、界面文字或屏幕信息才能成立的叙事
- 要求对尚未上传或无法查看的图片做精确视觉判断
- 露骨性内容、未成年人性化、非自愿性内容和过度血腥内容

## 安装

### Agent 工具用户

在 Codex、**Claude Code**、Workbuddy 等支持 Skill 安装的 Agent 工具中，直接发送：

```text
请从这个链接中安装skill：https://github.com/CyberJ0605/cinematic-video-prompt-engineer-skill
```

### 手动安装

如果你会使用 Git，可以克隆仓库：

```powershell
git clone https://github.com/CyberJ0605/cinematic-video-prompt-engineer-skill.git
```

然后把仓库内部的 `cinematic-video-prompt-engineer` 文件夹复制到你的 Skills 目录。不要把整个仓库外层目录当成 Skill 目录。

如果不使用 Git，可以在 GitHub 页面点击 `Code -> Download ZIP`，解压后进行同样的复制。

Windows 默认安装路径：

```powershell
C:\Users\你的用户名\.codex\skills\cinematic-video-prompt-engineer
```

如果你已把 skills 目录迁移到其他位置，例如：

```powershell
D:\Codex\skills
```

则放到：

```powershell
D:\Codex\skills\cinematic-video-prompt-engineer
```

安装后的结构应为：

```text
cinematic-video-prompt-engineer/
  SKILL.md
  agents/
    openai.yaml
  references/
    camera_movement_prompt_library.md
    emotion_performance_prompt_library.md
    reference_first_video_workflow.md
    style_patterns.md
    evaluation_cases.md
    vertical_9x16_adaptation.md
```

不要出现同名嵌套目录：

```text
cinematic-video-prompt-engineer/cinematic-video-prompt-engineer/
```

安装完成后，在新对话或下一次调用中输入 `$cinematic-video-prompt-engineer`。

### 不支持 Skill 安装的 AI 工具

ChatGPT 普通对话、DeepSeek、Kimi、通义、豆包等不支持 Skill 安装的工具，可以使用仓库中的通用提示词版本。

复制 [`PROMPT_VERSION.md`](PROMPT_VERSION.md) 中的内容给对应 AI，再提交剧情即可。通用提示词方便跨平台使用，但完整参考库、分阶段路由和评测能力以 Codex Skill 版本为准。

```text

```

### 直接生成视频提示词

```text
请用 $cinematic-video-prompt-engineer 处理这个剧情：
深夜医院走廊，男人收到母亲抢救失败的消息，却因为年幼女儿在身边，只能蹲下给她系鞋带，把眼泪憋回去。
```

### 先建立参考图

```text
请用 $cinematic-video-prompt-engineer 处理这个古装双人对话场景。

```

### 其他模式

- **精简模式**：用户明确说“直接给提示词”“不要分析”时，只输出最终视频提示词。
- **方向确认模式**：只在核心事实无法合理推断、用户明确要求先确认，或硬约束发生冲突时暂停确认。
- **连续短片模式**：维护人物、场景、关系、道具、声线、轴线、运动方向和情绪余波，继续输出后续片段。

方向确认格式：

```text
【剧情诊断】
【电影化改写策略】
【需要你确认的方向】
```

用户确认或授权Skill决定后，会沿用已经确定的方向继续，不重复询问同一个选择。

最终视频提示词长度按视频时长控制，诊断、策略和参考图提示词不计入：

| 视频时长 | 推荐目标 | 绝对上限 |
|---|---:|---:|
| 1-15 秒 | 简单 500-800；常规 800-1300；复杂 1300-2000 字符 | 2000 字符 |
| 16-24 秒 | 1600-2600 字符 | 3200 字符 |
| 25-30 秒 | 2200-3400 字符 | 4000 字符 |

上限不是目标长度。超过 3000 字符的 25-30 秒提示词，每一段额外描述都应直接服务于表演、声音、空间连续性、动作可读性或失败预防。

视觉核心：深夜公寓厨房、尚未收起的公文袋、丈夫站在客厅入口、妻子守在料理台内侧、两人之间无法跨越的中岛台。冲突从快速反击推进到妻子声音破裂，最后落在两人隔桌沉默。
结构判断：适合 30 秒四镜头对话交叉剪辑。先建立空间轴线，再把主要篇幅留给妻子的连续反击；中途切丈夫反应时让妻子台词作为画外音延续，最后回到妻子近景完成最脆弱的一句。
时长判断：韩语对白密度较高，但抢话、短暂重叠和局部加速都由人物情绪驱动，能够在 30 秒内完整呈现。先简化运镜和次要动作，不机械删除关键台词；最后预留约 1.5 秒沉默。
活人感处理：两个人都不是从第一秒开始失控。丈夫先用平静和事实口吻逃避商量，妻子先求证，再因他的理所当然被触发。眼神、呼吸、语速、停顿和身体距离必须围绕“谁有权决定共同生活”这一心理冲突发展。

【电影化改写策略】
采用写实韩剧家庭电影质感，遵守 180 度轴线：丈夫始终位于空间左侧，妻子位于空间右侧，中岛台是关系边界。镜头不做炫技环绕，冲突主要通过 OTS、CU、画外音和逐步收紧的景别推进。密集对白按语义节拍组织：通知 -> 追问 -> 防御 -> 抢话 -> 牺牲清单 -> 反问 -> 低声揭底。妻子的眼泪和声音破裂不能提前，丈夫只在听见“我辞掉工作”和最后一句时出现迟到的理解。

【建议先生成的参考图】
人物关系参考图：韩国都市夫妻，丈夫约三十八岁，深色通勤大衣、白衬衫略皱，疲惫克制；妻子约三十五岁，深灰针织衫、低马尾、淡妆和真实皮肤纹理。两人在现代公寓开放式厨房隔着中岛台对峙，丈夫在画面左侧客厅入口，妻子在画面右侧料理台内侧，深夜暖白吊灯与窗外冷蓝城市光混合，写实韩国家庭剧情电影质感，16:9。
场景参考图：首尔普通中产公寓开放式厨房与客厅，深夜，木色中岛台，水槽、两只水杯、未拆开的公文袋，背景落地窗可见冷蓝城市灯光，室内暖白吊灯为主光源，空间轴线和两侧站位清晰，无人物，无可读文字。

【最终视频提示词】
基础概括：30秒、16:9、写实韩剧都市婚姻冲突短片，原生同步韩语对白。深夜首尔公寓开放式厨房，丈夫通知妻子自己已申请调往釜山，妻子因再次被排除在共同决定之外爆发。四镜头对话交叉剪辑，遵守180度轴线：丈夫始终在空间左侧，妻子始终在右侧，中岛台保持在两人之间。表演由心理动机驱动，不是持续喊叫；愤怒先充当保护层，悲伤和声音破裂到后半段才出现。人物面孔、年龄、服装、声线、站位和道具全程一致。

角色与声音：丈夫38岁，低沉偏哑的成熟男中音，习惯压低音量讲道理，疲惫时句尾略短；妻子35岁，清晰偏冷的成熟女中音，前半段语速快但咬字准确，后半段音量下降、呼吸变碎。两人韩语口型与音节同步，抢话时各自独立动唇，不能交换台词或声音。

SHOT 1（0.0-4.8s）：MS，35mm，厨房与客厅双人构图。丈夫从左侧入口停下，把公文袋放到中岛台边缘，纸袋与木面发生真实接触，手指停留半拍才松开。他没有直视妻子，像在汇报已经完成的安排，用刻意平静的语气说：“이번 인사, 부산으로 신청했어. 다음 달부터 내려가.” 妻子在右侧擦杯子的动作逐渐停住，眼睛先抬向他，随后下巴才轻抬。杯子保持稳定，肩膀随屏住的呼吸微微抬起。最后一个词落下时切她的近景。

SHOT 2（4.8-12.0s）：丈夫肩后 OTS 转妻子 CU，50mm。4.8-7.0s，她先确认自己没有听错，眉心轻收，语速不快：“신청했다고? 나한테 말도 없이?” 丈夫在画外立刻防御：“말하면 또 싸울 거잖아. 어차피 당신은 안 갈 거고.” 7.0-9.5s，他说到“안 갈 거고”时，妻子短促吸气，身体向前半步，眼神攻击性上升，抢进句尾：“내가 왜 안 가는데?” 两人只重叠约0.3秒，丈夫随即让出声音。9.5-12.0s，她盯住他，右手指尖压住杯沿，指节轻微泛白，接着问：“당신이 한 번이라도 물어봤어?” 问完不立刻哭，嘴唇收紧，等待他的回答。

SHOT 3（12.0-23.0s）：切丈夫 CU 后再以妻子画外音延续。12.0-15.0s，丈夫下颌绷紧，目光仍对准右侧，语速加快为自己辩护：“나도 이 집 지키려고 버틴 거야.” 说到“지키려고”时身体微微前倾。15.0s妻子从画外抢入：“집?” 硬切回她的 BCU。15.0-19.5s，她发出一声没有笑意的短促气音，愤怒开始裂开，快速但清晰地说：“난 당신 어머니 병원 다니고, 내 일 그만두고, 세 번이나 이사했어.” 每列举一件事，声音都更低而不是更响；说到“내 일 그만두고”时目光短暂下落，喉咙收紧，下眼睑出现水光但泪不落。19.5-23.0s，她重新看回丈夫：“그런데 당신은 늘 혼자 결정해.” 最后半句明显放慢。镜头短暂切丈夫听者反应，他张口想反驳又停住，完成一次克制吞咽，眼神第一次避开。

SHOT 4（23.0-30.0s）：回到妻子 CU，85mm，极慢 Dolly In，只推进到更亲密的近景。丈夫画外音带着受伤和残余防御问：“그럼 나보고 뭘 어떻게 하라고?” 23.8-25.0s，妻子原本准备立刻反击，却在吸气时失败，嘴唇微张后闭上，停顿约0.5秒。25.0-28.5s，她把音量降下来，眼眶湿润但不崩溃，先说：“적어도 한 번은...” 省略处不是忘词，而是在决定是否说出最脆弱的事实。她重新看住丈夫，声音第一次轻微破裂：“내가 아직 당신이랑 같이 살고 싶은지, 먼저 물어봤어야지.” “같이 살고 싶은지”放慢，不抢拍。28.5-30.0s，她说完后手指从杯沿慢慢松开，没有擦泪；丈夫仍在模糊前景里静止，鼻腔缓慢呼气。两人隔着中岛台对视，无人补充台词，保留室内沉默和冰箱低频，直接结束，不淡出。

整体声音与光影：室内暖白吊灯为主光，从上方偏右照亮妻子，窗外冷蓝城市光勾出丈夫左侧轮廓；光源方向和夜景位置全程不变。无背景音乐。保留门锁余响、公文袋落桌、杯底轻触木面、冰箱低频、远处城市交通、衣料摩擦、真实吸气和吞咽。对白优先级最高，环境声不遮盖韩语，空间反射保持同一公寓声学；切丈夫反应时，妻子画外音仍从画面右侧传来。

负面约束：不要字幕、可读文字、水印或Logo；不要持续尖叫、舞台剧式挥手、突然流泪、固定假笑、空洞凝视或情绪跳变；不要人物换脸、服装变化、声线互换、口型错位、抢话时双方共用同一嘴型；不要越过180度轴线、站位互换、中岛台消失、杯子漂移、手指穿模、光影方向突变、无原因运镜、广告片磨皮或结尾台词刚说完立即截断。
